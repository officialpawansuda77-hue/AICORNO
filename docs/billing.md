# Dodo Payments launch setup

1. Rotate the Dodo API and webhook signing keys previously disclosed in chat. Also rotate the Supabase service-role key: an old fallback value was embedded in `src/lib/supabase.ts` and has been removed, but may exist in git history/deployed bundles. Do not commit secrets. Add the **new** keys to Vercel as `DODO_PAYMENTS_API_KEY`, `DODO_PAYMENTS_WEBHOOK_KEY`, and `SUPABASE_SERVICE_ROLE_KEY` (server-only).
2. Apply `supabase/dodo_billing.sql` in the production Supabase SQL editor. Confirm `SUPABASE_SERVICE_ROLE_KEY` is set in Vercel. Do not expose the service-role key to client code. Checkout refuses to start if the subscriptions table is unavailable.
3. Configure `DODO_STARTER_PRODUCT_ID` and `DODO_PRO_PRODUCT_ID` as the recurring subscription products (or the equivalent `NEXT_PUBLIC_DODO_*_PRODUCT_ID` variables). Verify that the checkout prices, currencies and billing intervals match the pricing cards; edit the displayed prices if they do not. Set `DODO_PAYMENTS_ENVIRONMENT=live_mode` with live products and a live API key; leave `test_mode` for test products and credentials.
4. Create a Dodo webhook endpoint at `https://YOUR_DOMAIN/api/webhooks/dodo`. Subscribe to subscription lifecycle events (at least active, updated, renewed, past_due, on_hold, paused, cancelled, expired, failed and plan_changed). Put that endpoint's signing key in `DODO_PAYMENTS_WEBHOOK_KEY`. Redeploy after setting the environment variables.
5. Test with Dodo's test environment first: sign in, purchase Starter and Pro using separate test users, confirm a verified `subscription.active` webhook creates a row, confirm image-only vs Pro video/skills access, test cancellation/expiration and a replayed/out-of-order event, then test the customer portal. Check Vercel and Dodo webhook logs for errors before enabling live mode.

Membership is calculated from the service-role-only `dodo_subscriptions` table for the signed-in Clerk user; no Clerk metadata fallback is used. Checkout return URLs do not grant access, and checkout is unavailable when subscription data cannot be retrieved. Only verified webhooks write subscription state; stale and duplicate events are ignored atomically. Access requires `active` status and a future `next_billing_date`. The portal manages changes/cancellation. A member with an active subscription cannot start another plan's checkout until the current subscription is ended, preventing two active plans at once.

**Known limitation:** premium prompt/skill text currently ships in public client data / public APIs; UI copy actions enforce membership but this is not DRM. Move premium content behind authenticated server endpoints before advertising it as confidential or unextractable. Production Clerk live keys, Dodo rotated credentials and SQL migrations are required before paid launch.
